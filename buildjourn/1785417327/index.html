Extraction Logic
▼

The skill scans the full conversation and identifies components across these categories:

CategoryWhat to Extract

Extraction rules: Only document what actually exists in the conversation. Capture exact IDs, URLs, and field names. Record design reasoning alongside decisions. Note what was tested vs. untested. Never fabricate.
Output Flow
▼

After extraction, the skill follows this sequence:

1. Present extracted component list for review ↓ user confirms or edits 2. Generate HTML (dark theme runbook, tabbed, expandable cards) 3. Save to /mnt/user-data/outputs/ and present_files ↓ user confirms publish 4. Minify HTML via Python re module 5. Call Make MCP — one call per document ├── Build Journal record (always) └── How-To Guide record (if separate doc chosen)
Single confirmation gate. Corrections happen at step 1 (extracted data review), not after the HTML is generated. This prevents rebuilding the HTML after every small edit.

session_date is a text field, not a date field. This is deliberate — same pattern as the Sales Brain's hubdb_updated_at. Storing dates as text prevents Airtable from reformatting and breaking downstream string operations.
Make MCP Write Pattern
▼

Every write follows these rules:

  • One record per call. Each MCP call creates a new Airtable record — no upsert behavior.
  • All fields in a single call. All five fields must be written in one call so they land on the same record.
  • Minify HTML before sending. Use Python re module. Never use shell-based sed — it causes encoding issues.
  • Absence of response = success. The Make MCP tool returns no output on successful writes.

Minification Script

import re def minify_html(html): html = re.sub(r'<!--.*?-->', '', html, flags=re.DOTALL) html = re.sub(r'\s+', ' ', html) html = re.sub(r'>\s+<', '><', html) html = re.sub(r'\s+/>', '/>', html) return html.strip()
If the MCP call times out: Large HTML payloads can exceed the Make timeout. Reduce HTML size (fewer expanded details, shorter code blocks) and retry. Do not use a placeholder + separate file download workaround.
