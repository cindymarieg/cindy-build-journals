Opportunity Chief — Scanner + Chief

AI-automation opportunity mining from meeting transcripts, scored against Cindy's real fit profile, delivered as a daily brief.

Complete · Live in production
Overview

What this automation does

Opportunity Chief watches every meeting transcript that lands in the Transcripts table, pulls out concrete AI-automation opportunities (things discussed out loud, and things nobody said but the conversation implies), scores each one against Cindy's actual business — Brave Pivot client work and Brave 10% Edge co-founder work, weighted toward whatever unblocks her content/visibility lead engine — and rolls it all into a short daily brief that names the one thing worth acting on and explains, plainly, why everything else can wait.

It is two systems working together: the Scanner, a Make.com scenario that turns raw transcripts into structured opportunity records, and the Chief, a set of Claude skills that score, cluster, and narrate those records into something Cindy actually reads over coffee.

Standard Operating Procedure

Step by step

1. A transcript arrives

Meeting transcripts (Gemini notes, mostly) land automatically in the Transcripts table in Airtable (appTQhmpFaaO5UNhh / tblvC2WkRCK9YedT6). No action needed here — this step already runs on its own.

2. Trigger the Scanner

Check the "Process for Opportunity Scanner" checkbox on the transcript's record. That field change fires an Airtable automation which posts to the Make webhook and kicks off scenario 4881675.

Annotation

The trigger is a checkbox rather than a button because Airtable automations only fire on a value change, not on a value being set to what it already is. If you need to reprocess a transcript, flip the checkbox to unchecked first, wait a beat, then check it again — flipping it too fast back-to-back has caused duplicate double-fires in testing (see Troubleshooting).

3. The Scanner extracts and writes opportunities

Inside the scenario: the transcript is fetched, passed through a first Claude call that extracts opportunities explicitly discussed, then through a second Claude call that looks for opportunities that were never said out loud but the conversation implies ("latent" opportunities). Each pass's output is parsed as JSON and written to the Opportunity Tracker (appgmiOEXAwLwi58f / tblKuOhO7j9e1ObRE). When both passes finish, the source transcript is marked processed and the trigger checkbox resets to false.

Annotation

Both Claude calls run on claude-opus-4-7, not a cheaper model — an earlier attempt to swap the first pass to a lighter model broke strict JSON-only output on rich, real transcripts (it worked fine on short ones, which is what made the bug easy to miss). Both prompts also carry an explicit instruction to return a valid, empty-but-well-formed JSON object rather than explanatory prose when a transcript has no real content — degenerate meeting notes ("no summary produced") were causing "Source is not valid JSON" failures before this was added.

4. Fit-score new opportunities

New Opportunity Tracker records land with fit_band empty. Run the opportunity-chief:fit-scoring skill against every record where that field is blank. It writes back a band (content_engine_build / core_business_work / worth_doing_later / not_mine), a 0–100 fit_score, and a one-sentence fit_reason.

Annotation

This step is currently manual (run by Claude on request) rather than wired into Make, because the Make MCP connector's write/pull tools for this base have proven unreliable — logged as an open item in the Feature Backlog and deliberately left alone per Cindy's instruction. Airtable field writes must use field IDs, not field names, or the API rejects the request outright.

5. Run the convergence/gravity scan

Export the Opportunity Tracker to CSV and run scripts/convergence_scan.py. It clusters opportunities by topic and flags two signals: convergence (the same idea surfacing across separate, unrelated meetings — a real signal that something matters) and gravity (one single engagement generating an unusual volume of opportunities, several still unbuilt).

6. Generate and deliver the brief

Run the opportunity-chief:morning-brief skill, which reads the scored corpus plus the convergence/gravity scan output and renders the daily HTML brief — one clear lead recommendation, gravity and convergence call-outs, and a "held silent" section that says plainly what didn't make the cut and why, so nothing feels dropped without explanation.

7. Watch for failure alerts

If either Claude pass or either JSON-parse step in the Scanner errors, a message posts automatically to Slack #automation-alerts naming which module failed and linking straight to the failed run in Make. The scenario itself may still auto-deactivate on a hard error — check isActive on the scenario and reactivate if needed.

Beyond meetings

Suggested other use cases

The Scanner-plus-Chief pattern — extract structured signal from unstructured text, score it against a real fit profile, cluster for recurring signal, narrate a single daily recommendation — isn't specific to meeting transcripts. A few places it could be pointed next:

Client email threads

Point the Scanner at client email chains instead of transcripts — the same "discussed vs. latent" two-pass extraction surfaces requests clients hinted at but never formally asked for.

Brave 10% Edge community posts

Scan Facebook group posts and comments from members like Bessy and Sabrina for recurring pain points — the convergence scan is built exactly for catching a problem that keeps resurfacing across different people.

Sales call recordings

Run discovery calls through the same extraction to catch objections and feature requests that come up in passing but never make it into CRM notes.

Content performance reviews

Feed livestream and post transcripts through fit-scoring alone (skip extraction) to flag which past content moments are strong enough to repurpose into the content engine — this is already what several of the batch-processed opportunities recommend doing manually.

Hiring or contractor interviews

Extract commitments and follow-ups from interview transcripts the same way opportunities are extracted from client meetings, so nothing promised in the room gets lost afterward.

Workshop feedback forms

Cluster open-ended workshop feedback with the same convergence logic used here — a complaint from one attendee is noise, the same complaint from five is signal worth the brief's top slot.
